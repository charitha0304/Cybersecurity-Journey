# Brute-Forcing a Stay-Logged-In Cookie
**Platform:** PortSwigger Web Security Academy  
**Category:** Authentication — persistent session / predictable token  
**Official lab:** https://portswigger.net/web-security/authentication/other-mechanisms/lab-brute-forcing-a-stay-logged-in-cookie  
**Status:** Solved

---

## Objective

Determine whether the persistent 'stay logged in' cookie was constructed in a predictable way that could be reproduced for another user without knowing their password.

## Observation and Methodology

I inspected the stay-logged-in cookie and identified that it was built from predictable components rather than from an unguessable random value. Using Burp Intruder's payload processing to reproduce the same construction for the target account, I identified a valid cookie value and used it to access the target user's session. The cookie values are redacted in the committed screenshots.

## Root Cause

The persistent-login token was derived from predictable inputs (a known encoding over guessable data) instead of being a high-entropy, server-side random value bound to the user. Because its structure could be reproduced, the token itself became guessable.

## Security Impact

An attacker who understands the token's construction can forge a valid persistent session for another user, bypassing the password entirely. Persistent cookies have long lifetimes, so the exposure window is large.

## Remediation

Make session and 'remember me' tokens long, random and unpredictable, generated by a cryptographically secure RNG and stored server-side (or signed so they cannot be forged). Do not derive them from the username, a password hash, or any guessable data. Set `HttpOnly`, `Secure` and an appropriate `SameSite` attribute, bind the token to the user, and expire/rotate it.

## Security Lessons

- A token's security comes from unpredictability, not from being encoded or hashed.
- Encoding (e.g. Base64) is not encryption and adds no secrecy.
- 'Remember me' mechanisms extend the lifetime of whatever weakness the token has.
